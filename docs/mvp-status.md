# SPB Fuel Intelligence — состояние

## Что работает

Полный путь `21 публичный источник → сырые ответы → нормализаторы → консервативный матчинг АЗС → дедупликация provenance → Evidence Engine → HTTP API или статический экспорт → мобильный веб‑интерфейс` работает и локально, и в GitHub Actions.

Публичная карта: <https://ogrebete-max.github.io/spb-fuel-intelligence/>. Обновление — слот примерно каждые 10 минут, публикация напрямую на GitHub Pages из этого же репозитория. Cron служит будильником, а сам прогон идёт цепочкой слотов: бесплатное расписание GitHub пропускает большую часть частых слотов и запускалось примерно раз в два часа.

Контрольный прогон: 21 из 21 канала локально, около 20 из 21 в Actions (один официальный источник периодически закрывается WAF от IP‑адресов раннера). Снимок — порядка 1 700 карточек АЗС и 30 000 grade‑level записей. Точные значения меняются при каждом обновлении.

## Семь состояний и достоверность

Для каждой пары «АЗС × марка» вычисляется одно из семи состояний: `CAN_REFUEL`, `LIKELY_AVAILABLE`, `CONFLICT`, `LIMITED`, `LIKELY_NOT`, `CONFIRMED_NO`, `NO_FRESH_DATA`.

Рядом показывается достоверность 0–100 %: сила самого сильного свежего сигнала, число независимо согласных provenance‑кластеров и доля израсходованного TTL. Это оценка данных, а не измерение остатка в резервуаре.

Противоположные сигналы объявляются конфликтом только при сопоставимом весе. Когда на одной карточке сходится дюжина агрегаторов, один слабый платёжный прогноз против официального остатка — сноска, а не повод стереть ответ.

## Почему это отличается от обычной карты

Обычная карта смешивает штатный ассортимент, цену и текущее наличие. Здесь они разделены: отсутствие ответа не становится отрицательным фактом, зависимые копии одного upstream не считаются независимыми подтверждениями, а конфликт показывается явно.

MVP ведёт временную историю по каждой паре «АЗС × марка»: переходы `не было → появилось` и `было → пропало`, длительность непрерывного состояния и уверенность перехода. Первое наблюдение не выдаётся за поставку. Если сохранённая история противоречит текущему ответу, она не показывается вовсе — карточка не может одновременно говорить «можно заправиться» и «нет непрерывно 13 ч».

## Телефон

Страница ставится на домашний экран как PWA: есть PNG‑иконки (Safari игнорирует SVG в `apple-touch-icon`), Apple‑мета для полноэкранного режима, service worker для офлайнового интерфейса. Список рендерится по 40 карточек, чтобы телефон не получал восемьдесят тысяч пикселей разметки за раз.

Поиск разделён на два намерения: обычный ввод фильтрует по сети и адресу, а «Проверить по адресу» или «Рядом со мной» трактует ввод как место и показывает АЗС в радиусе 5 км. Геокодирование вызывается только явным действием, кешируется и ограничено одним запросом в секунду — это соответствует [политике Nominatim](https://operations.osmfoundation.org/policies/nominatim/).

## Известные ограничения

- `gpnbonus.ru` — единственный источник класса `official_stock`; его WAF иногда отклоняет запросы из дата‑центра, и тогда строгих «МОЖНО ЗАПРАВИТЬСЯ» в публичном снимке становится меньше. Результат каждого коллектора публикуется в `static-data/collectors.json`.
- Карточек по‑прежнему больше, чем физических АЗС: строки одной сети на одной координате объединяются, но кросс‑брендовый alias‑registry не проверен вручную и намеренно не применяется.
- Административные районы Петербурга не размечены по валидированным полигонам; фильтр «Петербург / Область» работает по тексту адреса.
- Временных рядов пока мало для калиброванного прогноза «доживёт ли наличие до приезда».
- Канал `t.me/s/benzinspb78` публикует только положительные подтверждения, поэтому он никогда не даёт отрицательного сигнала.

Итог: приложением можно пользоваться как инструментом принятия решения; гарантированным realtime‑сервисом оно себя не называет и всегда показывает возраст и происхождение данных.
