# Аналитика использования и качества прогноза

## Что реализовано

В приложении работает собственная first-party аналитика без рекламных SDK:

- активные устройства и сессии по дням;
- поиск, нулевой результат и автоматическое расширение радиуса;
- выбор марки, зоны, режима карты и фильтра;
- воронка `открытие → поиск → карточка АЗС → маршрут → отметка на месте`;
- крупные зоны использования без точных координат;
- сравнение вероятности наличия с фактической отметкой водителя у АЗС;
- accuracy и Brier score по возрасту сигнала, статусу, уровню доверия и источнику;
- закрытая панель `/analytics.html` за административным ключом.

События агрегируются по суткам прямо в существующем KV `REPORTS`. Сырые события не сохраняются. Срок хранения агрегатов — 180 дней.

## Чего мы не собираем

- текст введённого адреса;
- точные или округлённые координаты пользователя;
- маршруты и историю перемещений;
- IP-адрес в аналитических записях;
- рекламный идентификатор, имя, телефон, почту;
- данные сторонних рекламных систем.

Координата используется только в браузере и немедленно превращается в одну из крупных зон: север, юг, запад, восток, центр Петербурга или Ленобласть. В панели зона скрывается, пока в ней не набралось хотя бы три события. `Do Not Track`, Global Privacy Control и ручное отключение в разделе «О данных» полностью выключают отправку.

Случайный идентификатор установки поступает только в наш Worker и HMAC-хешируется отдельным ключом на каждый день. В KV не записывается исходный идентификатор, поэтому дневные записи нельзя собрать в историю перемещений одного человека.

## Включение на Cloudflare

1. Обновить код существующего Worker содержимым `worker/spbfi-reports.js`.
2. В Worker → Settings → Variables and Secrets создать зашифрованный секрет `ANALYTICS_ADMIN_KEY` — длинную случайную строку не короче 24 символов.
3. Необязательно создать отдельный секрет `ANALYTICS_SALT`. Без него Worker безопасно использует закрытую часть уже созданного VAPID-ключа; наружу она не возвращается.
4. Проверить публичный health endpoint:

   ```bash
   curl https://spbfi-reports.ogrebete.workers.dev/analytics/health
   ```

5. Открыть `https://ogrebete-max.github.io/spb-fuel-intelligence/analytics.html` и ввести `ANALYTICS_ADMIN_KEY`. Ключ хранится только в `sessionStorage`, то есть исчезает при закрытии вкладки.

Проверка API панели:

```bash
curl -H "X-Analytics-Key: ВАШ_КЛЮЧ" \
  "https://spbfi-reports.ogrebete.workers.dev/analytics/dashboard?days=7"
```

## Как читать качество

`Accuracy` отвечает на грубый вопрос: совпало ли «скорее есть/скорее нет» с фактом. `Brier score` проверяет уже сам процент: прогноз 90%, который не сбылся, штрафуется сильнее прогноза 55%. Ноль — идеально, единица — максимально плохо.

Контрольным фактом считается только отметка, сделанная при известной геолокации не дальше 500 м от АЗС. Дистанционная отметка полезна группе, но не обучает оценку точности. Первые выводы по источнику или возрастной корзине допустимы после 30 проверок, устойчивые — после 100; панель до этого честно показывает размер выборки.

## Масштабирование

Для 10–20 пользователей суточные агрегаты в уже подключённом KV дешевле и проще отдельной базы. Известное ограничение — конкурентные записи в KV могут перезаписать друг друга, поэтому счётчики приблизительные.

Порог миграции на D1: более 100 активных пользователей в день, более 5% расхождения счётчиков с журналом запросов или необходимость произвольных когортных запросов. На бесплатном D1 доступно 5 млн прочитанных и 100 тыс. записанных строк в сутки, а также 5 ГБ хранения. После миграции тот же контракт `/analytics/events` останется без изменений.
