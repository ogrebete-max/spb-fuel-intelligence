## Как закрыть клуб (только после прямого «да» пользователя)

Сейчас `https://195.133.61.136/club/health` показывает `"mode":"test"`. Этап задаёт строка `CLUB_GATE` в `/etc/spbfi/env` на сервере. Подробнее — раздел «Этапы клуба» в `docs/club.md`.

| `CLUB_GATE` | Что видят |
|---|---|
| не задан (тест) | клуб видят только вошедшие, остальные пользуются приложением как раньше |
| `invite` | всем показывается «Есть приглашение в клуб своих? Вступить» |
| `closed` | без членства нельзя отмечать, видеть имена и получать уведомления; остальные видят экран входа |

Задуманный порядок: сначала `invite`, свои вступают по приглашениям («👥 Клуб» → «Создать приглашение» → «Отправить приглашение»), потом `closed`.

Команды выполняются в Git Bash на ПК пользователя, с ключом `~/.ssh/spbfi_club_ed25519` — тем же, что использует `server/remote.sh`:

```bash
spbfi() { ssh -i ~/.ssh/spbfi_club_ed25519 -o IdentitiesOnly=yes -o StrictHostKeyChecking=accept-new -o UserKnownHostsFile="$HOME/.ssh/known_hosts" root@195.133.61.136 "$@"; }
# Текущий этап. Выводится только эта строка: остальные строки файла — хеши секретов, их не показывать.
spbfi "grep '^CLUB_GATE=' /etc/spbfi/env || echo 'не задан: тест'"
# Закрыть. Чтобы открыть приглашения, вместо closed написать invite.
spbfi "sed -i '/^CLUB_GATE=/d' /etc/spbfi/env && echo CLUB_GATE=closed >> /etc/spbfi/env && systemctl restart spbfi-club"
# Проверить: должно быть "mode":"closed" и "club":true.
curl -s https://195.133.61.136/club/health
```

Вернуть тестовый режим: `spbfi "sed -i '/^CLUB_GATE=/d' /etc/spbfi/env && systemctl restart spbfi-club"`.

Ключ владельца и другие секреты не трогать и не спрашивать.

## Защита записи на сервере клуба и ответы, стареющие без сети (15.09.2026, по ревью)

Ревью нашло две серьёзные дыры, их закрыли до того, как ссылку разошлют шире.

**Сервер клуба (`worker/spbfi-reports.js`, метка `/club/health` → `write_guard: true`):**
- Раньше сервер верил полю `who` в отметке без пропуска участника. Id участников видны всем в `GET /reports`, так что любой мог отметить от имени участника. А отметка без `who` подписывалась IP-адресом.
- Теперь (`outsiderId`) телефон без пропуска подписывается только своим id (латиница, цифры, `-`, `_`), и это не может быть id участника. Иначе ставится `anon-` и начало sha256 от адреса. Сам адрес в `who` не попадает никогда.
- Лимиты: 20 отметок в минуту на телефон без пропуска (сверх лимита на адрес), `/subscribe` 6 в минуту с адреса, `/unsubscribe` 12.
- Отметка принимается, только если код АЗС — латиница, цифры и `:_.-` (до 64 знаков), иначе 400 `bad_station`. Координаты должны быть в прямоугольнике СПб и области (широта 58,4–61,9, долгота 27,5–35,9), иначе 400 `outside_area`.
- Подписки на уведомления: посторонние делят то, что остаётся от 300 после подписок участников (флаг `member` или `who` участника). Вытеснить участника они не могут.
- Клуб по-прежнему открыт (`mode: test`): отметки без входа разрешены, пока пользователь не скажет «да» на закрытие.
- Проверка: `worker/write-guard.test.mjs` (KV и D1, входит в `node worker/run-tests.mjs`).

**Ответы стареют и без нового снимка, и без сети:**
- Сборка пишет каждому ответу `expires_at` (`evaluate_grade`). Для ответа по источникам без времени это момент опроса плюс TTL, раньше такие ответы в телефоне не истекали никогда. В `grades-brief` ключ `x` теперь есть и у них.
- Открытое приложение раз в минуту проверяет `answersRanOut` и тихо перерисовывает список, пины и навигатор, если ответ истёк, в том числе без сети.
- Файл снимка, не загрузившийся без сети, больше не «застревает» до следующего снимка (`staticJson` забывает неудачную загрузку).
- Проверка: `tests/test_expiry.py`. Ещё `e2e/ageing-ui.mjs`: часы телефона уходят на 50 минут вперёд без сети, iPhone на списке, Android на экране карты.

**Прокрутка на Android (нашёл владелец 15.09.2026):**
- Список на Android не двигался пальцем, страница только «растягивалась». На iPhone всё было нормально.
- Причина: `html, body { overflow-x: hidden }` делал body отдельной прокручиваемой коробкой, в которой нечего прокручивать, а `overscroll-behavior: none` на body не пускал жест дальше, к странице. Safari так не делает.
- Теперь `overflow-x: clip`; старым iPhone без `clip` остаётся `hidden`.
- Проверка — `e2e/scroll-ui.mjs`. Палец в Chromium изображается сенсорными событиями CDP `Input.dispatchTouchEvent`; `synthesizeScrollGesture` в headless ничего не двигает. На iPhone проверяется сама причина: html и body не прокручиваемые коробки. Мобильный WebKit в Playwright не принимает ни колесо, ни палец.
